<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| backup dump file → restore target | A dump file is the recovery payload; if world-readable it leaks all DB contents |
| disposable container → host | The drill spins a throwaway postgres container; must not touch the dev/prod data volume |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-06-03 | Information disclosure | pg_dump output file | mitigate | Drill writes the dump to a `mktemp` path with `umask 077` (consistent with `pg_backup.sh` `chmod 600`), and removes it on exit (trap) — no world-readable dump left behind |
| T-06-04 | Tampering | disposable restore container vs dev volume | mitigate | The drill uses a distinct container name + port + ephemeral (no-volume / tmpfs) storage so it can never overwrite `postgres_data`; the dev DB is read-only source |
| T-06-05 | Information disclosure | synthetic vs production data | accept | Drill operates on locally-seeded synthetic reference/demo data only; no production rows or real credentials are present (stated in the script banner) |
| T-06-SC | Tampering | pip/uv installs | mitigate | No new packages installed; drill uses already-present `pg_dump`/`pg_restore`/docker. No legitimacy checkpoint required. |
</threat_model>
