# Phase 3 — UI Design Contract

> Visual and interaction contract for the Telegram Web App client circuit. Generated by
> gsd-ui-researcher, verified by gsd-ui-checker.

**Surface scope:** Surface C only — Telegram Web App (React + Vite). The internal dashboard
(Surface B / shadcn / Next.js) is Phase 4. The public landing (Surface A) is out of scope.

---

## Design System

| Property | Value |
|----------|-------|
| Tool | none — Telegram theme vars |
| Preset | not applicable |
| Component library | none — hand-rolled components styled with `var(--tg-theme-*)` |
| Icon library | lucide-react (line icons, consistent with dashboard mockups §1) |
| Font | `system-ui, sans-serif` (inherited from device / Telegram client) |

**Rule:** No hardcoded hex or RGB values in any component. Every color value MUST be a
`var(--tg-theme-*)` reference with a dark-mode fallback literal. Telegram injects its own
theme at runtime; the app adapts automatically.

**Sole exception:** the destructive color `#ef4444` is a hardcoded hex because the Telegram
theme spec exposes no `--tg-theme-*` destructive variable. This is the only permitted hardcoded
production color value.

Source: `webapp/src/App.tsx` (existing scaffold), `docs/polymer-intelligence-ui-mockups.md` §1
("Telegram Web App must honor Telegram theme variables"), dev-spec §6.2.

## Spacing Scale

Declared values (must be multiples of 4):

| Token | Value | Usage |
|-------|-------|-------|
| xs | 4px | Icon gaps, step-indicator dots, chip padding |
| sm | 8px | Field label-to-input gap, card inner spacing |
| md | 16px | Default section padding, card padding, page horizontal inset |
| lg | 24px | Between wizard step sections |
| xl | 32px | Top-of-screen vertical margin, section breaks |
| 2xl | 48px | Hero area vertical padding (home screen) |
| 3xl | 64px | Not used in Phase 3 |

Exceptions:
- Touch targets for primary buttons: minimum 44px height (iOS HIG / WCAG 2.5.5 touch target).
  Button padding is `12px 20px` which achieves ≥44px on standard line-height. Enforced in code
  via `min-height: 44px`.
- Step indicator dots: 8px diameter, 4px gap (xs).
- Card border-radius: 12px (matches existing `card` style in App.tsx).

Source: existing `App.tsx` padding values (4px, 8px, 12px, 16px) normalized to 4-point scale;
12px card margin rounded to nearest 4 token (use 12px as a named constant `card-gap: 12px`
within this phase only — not a full scale token).

## Typography

| Role | Size | Weight | Line Height | CSS Var |
|------|------|--------|-------------|---------|
| Body | 14px | 400 | 1.5 | `var(--tg-theme-text-color)` |
| Label / hint | 13px | 400 | 1.4 | `var(--tg-theme-hint-color)` |
| Card title / section heading | 15px | 600 | 1.3 | `var(--tg-theme-text-color)` |
| Screen heading / H1 | 18px | 600 | 1.2 | `var(--tg-theme-text-color)` |

Exactly 4 sizes (13, 14, 15, 18), exactly 2 weights (400 regular, 600 semibold).

Source: sizes and weights extracted verbatim from `webapp/src/App.tsx` (`headerTitle` 18/600,
`cardTitle` 15/600, `accentButton` 14/600, `cardText` / `headerSubtitle` 13/400). Weight 600
used for all heading contexts; weight 400 for body, hints, labels.

**Number display rule:** Request confirmation numbers (`REQ-YYYY-MM-DD-NNNNN`), volume figures,
and prices render at 15px semibold (card title role).

## Color

All colors are Telegram theme variables. Hex fallbacks are for dev/browser testing only and
MUST NOT appear in production media queries or conditional styles.

| Role | CSS Variable | Fallback (dev only) | Usage |
|------|-------------|---------------------|-------|
| Dominant (60%) — background | `var(--tg-theme-bg-color)` | `#1e293b` | Page background, full-screen container |
| Secondary (30%) — surfaces | `var(--tg-theme-secondary-bg-color)` | `#0f172a` | Cards, input backgrounds, header |
| Accent (10%) — primary action | `var(--tg-theme-button-color)` | `#10b981` | See accent reserved-for list below |
| Accent text on button | `var(--tg-theme-button-text-color)` | `#ffffff` | Text on accent buttons only |
| Body text | `var(--tg-theme-text-color)` | `#f8fafc` | All primary text |
| Hint / muted text | `var(--tg-theme-hint-color)` | `#94a3b8` | Labels, secondary copy, placeholders |
| Link | `var(--tg-theme-link-color)` | `#38bdf8` | Inline text links only |
| Destructive | `#ef4444` with 0.15 background-opacity | N/A — sole permitted hardcoded hex (no tg-theme equivalent) | Cancel/delete actions only (see below) |
| Border / divider | `var(--tg-theme-secondary-bg-color)` at 1px | `#334155` | Card borders, field underlines |

**Accent (`var(--tg-theme-button-color)`) reserved for:**
1. Primary Telegram MainButton (Далее / Отправить) — controlled by `@telegram-apps/sdk`
2. "Оставить заявку" button on Home screen
3. Confirmation screen success check icon fill
4. Active step dot in the 4-step wizard step indicator
5. Positive status chips: "Новая заявка", "Подобрано"

Accent is NOT used for: field borders on focus (use `var(--tg-theme-link-color)`), status
chips other than those listed above, or nav elements.

## Interaction Contracts

### Wizard Navigation
- **Forward:** MainButton "Далее" — disabled until current step passes zod validation; triggers
  per-step validation on tap, shows inline field errors.
- **Backward:** Telegram BackButton — navigates to previous step; does NOT clear state (zustand
  persists across minimize, D-01).
- **Submit (Step 3 → Confirm):** MainButton changes label to "Отправить"; tap fires
  `POST /webapp/requests` then (if files) sequential `POST /webapp/requests/:id/files`;
  shows loading state on MainButton (disable + spinner); on error shows ErrorBanner.
- **Step indicator:** read-only visual only; tapping past dots does NOT navigate (one-way wizard).

### File Upload (C-04)
- Accept: `.pdf`, `.xlsx`, `.xls`, `.jpg`, `.jpeg`
- Reject immediately (before upload) if: file count > 5, individual file > 10 MB, MIME type
  not in allowlist. Show inline error beneath the file drop zone.
- Each accepted file shows: filename (truncated to 24 chars + ellipsis), size in KB/MB, remove
  (×) button.
- Files are NOT uploaded until after `POST /webapp/requests` succeeds; upload runs sequentially
  (not parallel) per file to stay within 3G budget.

### "Мои заявки" (C-06)
- List ordered by `created_at DESC`.
- Pull-to-refresh gesture supported via `@telegram-apps/sdk` haptic feedback on refresh.
- Loading skeleton: 3 placeholder cards at card height (48px) with pulsing `secondary-bg` fill.
- On successful status-change push (bot notification), the list re-fetches automatically when
  the Web App is foregrounded (visibility change event).

### Language Toggle (C-09)
- RU / UZ toggle — two-option segmented control.
- On change: updates `clients.preferred_language` via `PATCH /webapp/me`; updates
  `react-i18next` language immediately (no page reload); persists to localStorage as fallback.
- Default: detected from Telegram `language_code` on first login (D-04); falls back to `ru`
  if `language_code` is neither `ru` nor `uz`.

### Telegram Native Controls
- **MainButton:** controlled via `@telegram-apps/sdk` `mainButton` object. Color = Telegram
  native (respects user's Telegram theme). Text = "Далее" steps 1–2, "Отправить" step 3,
  hidden on non-wizard screens.
- **BackButton:** shown on C-02 through C-07; hidden on C-01, C-05 (confirmation), C-09.
- **HapticFeedback:** `impactOccurred('light')` on step advance; `notificationOccurred('success')`
  on confirmation; `notificationOccurred('error')` on validation failure or API error.

## Performance Constraints

Derived from REQ-nfr-performance and the 03-CONTEXT.md.

| Constraint | Value | How to meet |
|------------|-------|-------------|
| Bundle size | ≤ 300 KB gzip | Code-split by route (React.lazy); do NOT import full lucide-react — import named icons only |
| First paint on 3G | ≤ 3 s | Home screen renders with static content only; no API calls block initial paint |
| Request submission to dashboard | ≤ 10 s | `POST /webapp/requests` must complete and the record must be readable within 10 s of tap |
| Status notification | ≤ 30 s | Celery `notify` queue task fires ≤ 30 s after status write |
| Image assets | 0 | No raster images in UI; use CSS + lucide icons only |

The `vite.config.ts` `chunkSizeWarningLimit: 500` is set; the executor must ensure the main
chunk stays under 300 KB gzip (not just uncompressed).

## Accessibility

| Requirement | Rule |
|-------------|------|
| Touch targets | ≥ 44 × 44px for all interactive elements (buttons, file remove, nav) |
| Icon-only actions | Every icon-only control has an `aria-label`. The `FileUploader` × remove button uses `aria-label="Удалить файл {name}"` (key `fileUploader.remove`); icon-only nav items carry a text label or `aria-label` |
| Color independence | Status chips use both color AND text label — never color alone |
| Form fields | Every `<input>` / `<select>` / `<textarea>` has an associated `<label>` with `htmlFor`; errors referenced via `aria-describedby` |
| Language attribute | `<html lang="ru">` / `<html lang="uz">` updated on language toggle |
| Focus management | On wizard step advance, focus moves to the step heading (H2) via `useEffect` + `ref.current.focus()` |
