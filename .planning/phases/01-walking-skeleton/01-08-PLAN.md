<objective>
Close UAT Gap 1 / SC#1 (blocker): "docker compose up brings up nginx; /health returns OK". Plan 01-05 added an nginx service and the mandatory events {} block, so the config SYNTAX is valid — but `nginx -t` under dev-equivalent conditions still produces two hard `[emerg]` startup failures, so nginx never actually comes up in the dev stack:

1. `location /dashboard/` proxies to `http://dashboard:3000` (nginx.conf line ~117-118), but the dev compose intentionally excludes the dashboard service (compose header line 11) → nginx resolves all upstream hostnames at startup → `[emerg] host not found in upstream "dashboard"`.
2. The `listen 443 ssl` server block loads `/etc/letsencrypt/live/example.com/fullchain.pem` (line ~67-68), which the dev nginx service never mounts → `[emerg] cannot load certificate`.

Either failure crashes nginx at boot, so the "walking skeleton walks" success criterion is not met. nginx.conf is effectively a production config (443/ssl + letsencrypt + dashboard upstream) reused verbatim by the dev compose.

Purpose: The deployable end-to-end skeleton must actually stand up — a dev compose stack where nginx boots and proxies `/health` is the backbone every later phase plugs into.
Output: A dev nginx that boots with no [emerg], serves over HTTP, has no boot-time dependency on the absent dashboard upstream, and through which `/api/v1/health` returns 200; re-verified with a live `docker compose up`.
</objective>

| nginx → api:8000 | Internal proxy hop; only `/api/` is exposed through nginx; postgres/redis stay on the internal compose network |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-08-01 | Denial of Service (self-inflicted boot failure) | dev nginx startup | mitigate | Remove the boot-time dashboard DNS resolution and the unmounted-cert load so nginx actually starts and the stack is usable; without this the whole dev backbone is down |
| T-08-02 | Information Disclosure (TLS downgrade in dev) | dev nginx serving HTTP-only | accept | Dev stack runs HTTP-only on localhost; production TLS config (443/ssl + letsencrypt + HSTS) is preserved in the prod nginx.conf / behind the resolver guard and is unchanged for prod deployment |
| T-08-03 | Spoofing (credential stuffing) | /api/v1/auth/login rate limit | mitigate | The `limit_req_zone` + auth-login burst block is carried into the dev server block so the rate limit is effective once nginx boots (previously moot because nginx would not start) |
| T-04-05 | Elevation of Privilege | exposed internal services | mitigate | Dev nginx publishes only port 80; postgres/redis/api ports remain on the compose network except where already published for dev convenience (unchanged) |
| T-03-SC | Tampering | container base image (nginx:stable) | accept | Official Docker Hub image; no third-party package installs added by this plan |
