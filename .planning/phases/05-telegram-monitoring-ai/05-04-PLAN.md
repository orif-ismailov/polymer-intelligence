<objective>
Wire the 05-03 service layer into the live pipeline: the Celery `parse_telegram_item` orchestrator that takes a pending telegram `raw_item`, runs the budget gate → LLM extract (or rule-based fallback on `BudgetExceeded`) → journals exactly one `parse_runs` row → writes a `signals` row with the `ai` JSONB stamped (lead_score, classification, needs_review, model, prompt_version, scored_at), routing `confidence < 0.5` to `needs_review` and dead-lettering `InstructorRetryException`. Plus: the nightly catch-up task that reprocesses budget-deferred items, the deduped admin budget alert, the per-source 7-day token-spend surface, and the dashboard `needs_review` wiring (the disabled Phase-4 `NeedsReviewChip` becomes a real filter).

This realizes ROADMAP SC#2 (one LLM call, strict JSON, journaled model+prompt_version+tokens, confidence<0.5→needs_review), SC#4 (budget→pending+fallback+nightly catch-up+admin alert, per-source 7-day spend), and the lead-score write half of SC#3.

Purpose: This is where the guardrails become enforced behavior (AI-SPEC §6 G1-G5): no unattributable signal, no partial record on validation failure, no auto-publish of low-confidence or budget-degraded results, no silent budget burn. The orchestrator is the only place that touches the DB on behalf of extraction.

Output: the orchestrator + ai_signal_service + nightly catch-up + budget alert + feed/admin surfaces + the enabled dashboard chip.
</objective>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| LLM result → signals table | Validated ExtractionResult crosses into the actionable feed; needs_review gates auto-publish |
| raw_item → parse_runs journal | Every extraction must be attributable (audit trail) |
| feed needs_review filter param → SQL | Staff-supplied query param must stay parameterized |
| budget counter → admin alert | Cost-control breach must notify, not silently degrade |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-05-15 | Repudiation | unattributable signal | mitigate | G5: write_parse_run (model/prompt_version/tokens) ALWAYS precedes the signal write; ordering asserted in Test 7 |
| T-05-16 | Tampering | partial/invented signal on validation failure | mitigate | G3: InstructorRetryException → dead-letter; no signal write on the failure path (Test 4) |
| T-05-17 | Elevation of privilege | low-confidence lead auto-actioned | mitigate | G2: confidence<0.5 → ai.needs_review=true, never auto-published HOT; analyst must accept (Test 2) |
| T-05-18 | Denial of service | budget exhaustion blocking the pipeline | mitigate | G4: BudgetExceeded → rule_based_extract (pipeline continues) + nightly catch-up + deduped admin alert; never indefinite block (Test 5) |
| T-05-19 | Tampering | SQL injection via needs_review/feed filter | mitigate | Bound parameter only (CAST/:param), mirrors T-04-02; no string interpolation |
| T-05-20 | Information disclosure | raw_response in parse_runs leaking secrets | accept | raw_response is the model completion (channel text + extraction), internal RBAC-gated; no credentials present in the completion |
</threat_model>
