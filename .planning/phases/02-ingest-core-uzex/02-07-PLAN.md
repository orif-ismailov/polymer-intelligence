<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| backup artifact → restore | dump files contain the full DB (PII, credentials-adjacent data) and must be access-controlled |
| seeded source.config → adapters | seeded selectors/URLs drive live fetches (must pass the SSRF guard + test-before-enable) |
| live external fetch → pipeline | end-to-end verification touches untrusted external responses |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-02-23 | Information Disclosure | pg_dump backup files left world-readable | mitigate | pg_backup.sh writes dumps with restrictive perms (umask 077 / chmod 600) to a non-public dir; runbook documents secure storage off the web root |
| T-02-24 | Tampering | a seeded source enabled before a passing test (bypassing the invariant) | mitigate | seed_sources sets is_enabled=false + last_test_ok_at NULL; enabling requires a passing Test (sources invariant) — verified in the seed test |
| T-02-25 | Denial of Service | a crashed worker silently stops all ingest | mitigate | `restart: unless-stopped` auto-restarts worker/beat; the */5 health task + 3-strike alert surface any persistent outage (REQ-nfr-reliability) |
| T-02-26 | Repudiation | restore procedure undocumented → unrecoverable | mitigate | docs/runbook-backup-restore.md gives a step-by-step restore with the ≤2h target; backup retention (14d/8wk) documented |
| T-02-SC | Tampering | npm/pip/cargo installs | accept | No new package installs in this plan (pg_dump/pg_restore are postgres client tools, not pip packages) |
</threat_model>
