<objective>
Build the measurable acceptance gate and the lead-score recompute path. The eval harness (mirroring the shipped `test_uzex_accuracy.py`) scores FROZEN predictions against the customer's 100-message golden set and asserts the TZ §6.1.3 contract: relevant-signal **recall ≥ 80%** (D1) and per-field **precision ≥ 85%** (D3-D9) — deterministic, key-free, runnable in CI with no live model. Plus: the golden-set/synonym loader with a customer-input-or-example-fixture resolution (the 100-message set + synonyms are gated customer inputs, so plans run against committed example fixtures and switch to the real set when delivered), the per-field match rules (synonym-aware grade, price tolerance band) made executable, the eval CLI for the acceptance review, and the `rescore_on_prompt_version_change` backfill that overwrites `signals.ai` when the scoring prompt version changes (REQ-lead-scoring "recomputed on prompt-version change").

This realizes ROADMAP SC#5 (recall ≥80% / precision ≥85% via the eval tool + golden set) and the recompute half of SC#3.

Purpose: Eval is in-scope and measurable, not a manual afterthought (phase_specific_constraints #6). The metric math is unit-tested independently so it cannot silently drift, and the gate scores frozen predictions so it is reproducible and CI-safe.

Output: the `tests/parsing/{eval_config,eval_metrics,golden_loader,test_eval_metrics,test_telegram_accuracy}.py` harness + golden/synonym example fixtures + the eval CLI + the lead-score recompute service/task.
</objective>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Customer golden set file → eval harness | Externally-supplied JSON read into the gate; malformed input must fail loudly, not silently pass |
| Frozen predictions → gate assertion | The replay artifact must be pinned to a known prompt_version or the gate is meaningless |
| Prompt-version bump → signals.ai overwrite | Recompute mutates the only mutable AI output; must stay attributable |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-05-21 | Tampering | gate scoring against a stale/unknown prompt version | mitigate | Frozen predictions pinned to prompt_version v1; refresh requires --runlive + commit; gold defines is_relevant — gate is reproducible (§5.6) |
| T-05-22 | Spoofing | a green gate that secretly made a live LLM call (flaky/costly) | mitigate | Gate reads frozen predictions only; key-free import test asserts no live call under the CI placeholder key (§5.4) |
| T-05-23 | Tampering | metric drift silently relaxing the gate | mitigate | eval_metrics is unit-tested independently on synthetic pairs with known answers (§5.6) |
| T-05-24 | Repudiation | re-scored signal not attributable to a prompt version | mitigate | rescore overwrites signals.ai with scoring_prompt_version + scored_at; immutable raw_item/parse_run make it re-derivable (§7) |
| T-05-25 | Information disclosure | golden set / customer PII in committed fixtures | mitigate | Only the EXAMPLE fixture is committed; the real customer set resolves from GOLDEN_SET_PATH and is gitignored (customer-input handoff) |
</threat_model>
