<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Telegram client → /webapp/* API | Untrusted initData header crosses here; identity must be cryptographically verified, never trusted from body |
| Web App → backend file upload | Untrusted file bytes + filenames cross here; type/size/path must be validated server-side |
| Backend → MinIO | Object keys derived from user input must be traversal-safe |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-03-01 | Spoofing | get_current_client / initData | mitigate | HMAC-SHA256 verify per Telegram algorithm (secret=HMAC("WebAppData", BOT_TOKEN)); `hmac.compare_digest`; reject on mismatch (Task 2) |
| T-03-02 | Tampering | initData replay / forged identity | mitigate | 24 h TTL on auth_date (TELEGRAM_INIT_DATA_TTL_SECONDS); identity read only from verified payload, never request body (Task 2) |
| T-03-03 | Information disclosure | auth failure messages | mitigate | Generic 401 "Authentication required" for every failure path — never reveal which check failed (Task 2) |
| T-03-04 | Tampering | malicious file upload (wrong type) | mitigate | Magic-byte MIME validation (not extension); allowlist PDF/xlsx/JPEG; reject before MinIO write (Task 3, D-08) |
| T-03-05 | Denial of service | oversized / too-many files | mitigate | ≤10 MB per file enforced in validate_upload; MAX_FILES=5 contract (Task 3, D-08) |
| T-03-06 | Tampering | path traversal in storage_path | mitigate | S3 key built from sanitized basename + random token; raw user filename never used as key (Task 3) |
| T-03-SC | Tampering | npm/pip installs (aiogram, boto3, python-multipart, moto) | mitigate | Blocking human legitimacy checkpoint (Task 0) — pypi.org verification before install |
</threat_model>
