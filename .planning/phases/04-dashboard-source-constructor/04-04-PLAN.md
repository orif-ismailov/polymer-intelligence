<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Browser → /requests* | Status-change + team actions cross to the DB and audit log |
| Browser → /admin/users | Staff PII (email/role) crosses to client |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-04-10 | Tampering/Elevation | PATCH /requests/{id} | mitigate | `require_role(admin, analyst, trader)`; viewer -> 403 (asserted in test); status only via transition_status server-side enforcement |
| T-04-11 | Tampering | invalid status transition | mitigate | `transition_status` raises ValueError on illegal transition -> 422 (Pitfall 5; never set status directly) |
| T-04-12 | Repudiation | team actions | mitigate | Every action writes audit_log via write_audit in the same transaction (db.flush, router commits); staff_user_id from verified JWT, never body |
| T-04-13 | Info Disclosure | GET /admin/users | mitigate | require_admin; SELECT excludes password_hash (asserted by token-absence check) |
| T-04-14 | Error/Crash (DoS) | Contact Buyer with NULL telegram_user_id | mitigate | contact_available derived from telegram_user_id IS NOT NULL; no tg://user?id=None link built (Pitfall 6) |
| T-04-SC | Tampering | pip installs | accept | No package installs in this plan |
</threat_model>
