# Онбординг-карта IMEX AI

Материал для визуальной карты продукта и ролей. Собран **вождением живого продукта в
браузере** (`localhost:5173` портал, `localhost:3000` дашборд) на обнулённой базе, а не по
документации и не по коду.

## Что здесь

| Файл | Что это |
|---|---|
| `findings.md` | Находки, дефекты и открытые вопросы — по мере обнаружения |
| `roles.md` | Роли, матрица фич, что каждая может и не может |
| `flows/` | Журналы потоков по фазам: шаг → экран → действие → результат → состояния |
| `board-model.json` | Единое описание доски, из которого генерируются оба носителя |
| `shots/` → `../../.tmp-onboarding/shots/` | Скриншоты (вне git) |

## Носители результата

Оба генерируются из `board-model.json`, поэтому разойтись не могут:

1. **`.excalidraw`** — сцена для excalidraw.com (перетащить файл на холст).
2. **Одностраничный HTML** — читаемая карта с навигацией по ролям.

FigJam-доска начата (https://www.figma.com/board/nvB8kXCluldAh6XU2ARVcK), но **заброшена**:
тариф Figma Starter даёт 20 вызовов MCP в месяц, лимит исчерпан после секции 0. Готовы
обёртка, заголовок и легенда (цвета, формы, бейджи происхождения, навигация по 14 секциям).

## Визуальный язык

Цвет отвечает на «кто действует», форма — на «что это за шаг», бейдж — на «откуда мы знаем».

| Цвет | Значение |
|---|---|
| 🔵 синий | действие пользователя |
| 🟣 фиолетовый | система делает сама (Celery, бэкенд) |
| 🟡 жёлтый | бизнес-правило |
| 🟢 зелёный | успешный исход |
| 🔴 красный | ошибка, отказ, отклонение |
| ⚪ серый | состояние сущности, справка |
| 🟠 оранжевый | внешний рельс: Didox, E-IMZO, госреестр, банк |

| Бейдж | Значение |
|---|---|
| ✓ | проверено в браузере — есть запись сети или строка в Postgres |
| ⌘ | из кода — прочитано в исходниках, в браузере не выполнено |
| ? | требует уточнения — воспроизвести не удалось |

## Стенд, на котором всё снято

База обнулена `DROP SCHEMA` → `alembic upgrade head` (голова `0047`) → 5 сидеров
(`seed_reference`, `seed_staff`, `seed_sources`, `seed_substances`, `seed_contract_templates`).
Redis и бакет MinIO очищены. Все данные создавались кликами по живому UI.

| Переключатель | Значение | Почему так |
|---|---|---|
| `gov_registry_mode` | `didox` | живой госреестр, реквизиты подтягиваются по ИНН |
| `didox_mode` | `live` | документный рельс включён (контур `testapi3.didox.uz`) |
| `verification_auto_approve` | `false` | чтобы существовало ручное ревью сотрудника |
| `escrow_mode` | `stub` | переводы отмечает оператор вручную |
| `EIMZO_STUB` | `true` | **подпись принимается без проверки криптографии** |

Вход: OTP-код всегда `000000` (`OTP_DEV_CODE`, работает при `DEBUG=true` +
`SMS_PROVIDER=console`). Staff: `admin@polymer.uz`.

Через Didox резолвятся ровно два ИНН — **312616547** (IMEX) и **590640341** (сам DIDOX).
Остальные сгенерированы вручную и в реестре не найдутся.

Модуль E-IMZO видит пять корпоративных ключей: `562353400`, `514890380`, `575013376`,
`537302090` и `312616547` (наш). Пароль у всех `12345678`.
