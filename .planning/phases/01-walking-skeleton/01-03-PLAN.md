<objective>
Build the dashboard authentication and role-based access control backbone: argon2 password hashing, JWT issuance/verification (access 15 min + refresh 7 d in an httpOnly cookie), `POST /auth/login` and `POST /auth/refresh`, a `require_role` dependency enforcing the admin/analyst/trader/viewer roles, an audit_log writer, and seeded staff users (one per role).

Purpose: This is the Phase-1 security backbone. It implements REQ-roles (the four staff roles and their access boundaries) and REQ-nfr-security (argon2 hashing, JWT auth split for the dashboard, never trusting client identity, audit_log on privileged actions). All later dashboard phases authenticate through this.
Output: A working login flow returning a real JWT + httpOnly refresh cookie, a reusable role guard, audit logging, and seeded role accounts to test against.
</objective>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| browser → /auth/login | Untrusted credentials cross here; brute-force + injection surface |
| client → protected API (Bearer JWT) | Token must be the sole source of identity; never trust body-supplied ids |
| refresh cookie ↔ access token | Long-lived secret stored in httpOnly cookie; access token short-lived |
| staff role → privileged route | Authorization boundary across admin/analyst/trader/viewer |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-03-01 | Information Disclosure | password storage | mitigate | argon2-cffi hashing (salted); plaintext never stored or logged; login returns a generic 401 (no user-enumeration) |
| T-03-02 | Spoofing | token forgery | mitigate | JWT signed with `JWT_SECRET` (HS256); `decode_token` verifies signature; tampered tokens rejected (tested) |
| T-03-03 | Tampering / Replay | token-type confusion | mitigate | `type` claim distinguishes access vs refresh; cross-use rejected (tested); access expiry 15 min limits replay window |
| T-03-04 | Elevation of Privilege | role bypass | mitigate | `require_role` checks the role from the verified token AND confirms is_active; admin-only route 403s a viewer (tested); authorization enforced at the API, not the UI |
| T-03-05 | Information Disclosure | refresh token theft | mitigate | Refresh token in `HttpOnly`+`Secure`+`SameSite` cookie (not JS-readable); 7 d expiry; rotated on refresh |
| T-03-06 | Spoofing | identity from request body | mitigate | All identity derives from the verified JWT `sub`; no endpoint reads staff/client id from the body (dev-spec §10.5) |
| T-03-07 | Repudiation | privileged actions untraced | mitigate | `audit_service.write_audit` records login + status changes (action/entity/entity_id/staff_user_id) per REQ-nfr-security |
| T-03-08 | Elevation of Privilege | ORM SQL injection at login | mitigate | Email lookup uses parameterized SQLAlchemy queries; no string-built SQL |
| T-03-SC | Tampering | argon2/jwt deps | mitigate | argon2-cffi + the JWT lib are part of the canonical locked stack (plan 01-01 pyproject); no new third-party packages introduced |
</threat_model>
