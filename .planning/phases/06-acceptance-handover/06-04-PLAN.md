<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| internet → nginx (80/443) | Only ingress; everything else is on the internal docker network |
| .env (host) → containers | Secrets cross from the host `.env` into container env at runtime |
| container ↔ container | api/worker/beat/userbot share DB/Redis on a private network |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-06-09 | Information disclosure | secrets in compose defaults | mitigate | All secrets via `${VAR}` from `.env` (outside repo); no real secret literals committed; BOT_TOKEN/WEBHOOK_SECRET/TG_API_*/TG_SESSION_STRING/POSTGRES_PASSWORD have no weak inline default so a misconfigured deploy fails fast instead of running insecurely |
| T-06-10 | Elevation of privilege / exposure | direct port exposure of api/db/redis | mitigate | Only nginx publishes host ports (80/443); postgres/redis/api/worker/beat/userbot/dashboard bind to the internal network only — least privilege, no DB/Redis reachable from the internet |
| T-06-11 | Tampering | plaintext transport | mitigate | nginx mounts the TLS `nginx.conf` (443 ssl + 80→443 redirect + letsencrypt cert paths) so all external traffic is HTTPS (TZ §5 "HTTPS повсеместно") |
| T-06-12 | Spoofing | aiogram webhook endpoint | mitigate | Webhook served on the api service behind nginx TLS; `WEBHOOK_SECRET` required (no default) so unsigned webhook calls are rejected — single bot ingress, no separate exposed bot container |
| T-06-SC | Tampering | image/package provenance | mitigate | Compose pins base images (`postgres:16-alpine`, `redis:7-alpine`, `nginx:stable`) and builds app images from the audited backend/dashboard Dockerfiles — no new third-party packages introduced. No legitimacy checkpoint required. |
</threat_model>
