<objective>
Build the LLM extraction service layer against the 05-01 contract: the single-call `extract_signal` (instructor + Anthropic SDK, `Mode.TOOLS`, `create_with_completion`, `temperature=0`, `max_retries=2`, prompt-cached system block), the Redis daily token-budget gate (`check_and_reserve_tokens` raising `BudgetExceeded`), the rule-based fallback used when the budget is exhausted, the lead-scoring pass (0-1 + HOT/MEDIUM/LOW), and the message-text preparation guard (truncate forwards, skip blank/media). This is a pure service layer — it makes the LLM call but does NOT touch the DB or Celery; the orchestration that journals to `parse_runs` and routes to `needs_review` is 05-04.

Per AI-SPEC §4, the planner-carried risk is the transport choice: a 10-20 row spike comparing instructor TOOLS vs native tool-use is run first and the winner pinned. The extractor records which path it uses so `parse_runs.parser` ('llm_extract_tools' / 'llm_extract_native') is attributable.

Purpose: Isolate the model-layer vendor lock-in behind one `extractor` interface (AI-SPEC §2 "Vendor Lock-In Accepted: isolated behind a single extractor service"), make the budget a hard, testable control (REQ-llm-budget), and make the fallback a real rule-based extraction (NOT a "skip for now" stub — scope_reduction_prohibition).

Output: `backend/parsing/{extractor,budget,fallback,lead_scoring,text_prep}.py` with full unit coverage that mocks the Anthropic client (no live LLM call in CI).
</objective>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Untrusted channel text → LLM extractor | Attacker-controllable message content is the user turn sent to Claude — the prompt-injection/jailbreak surface |
| LLM output → ExtractionResult | Model output is untrusted until it passes Pydantic validation |
| Token spend → Redis budget counter | Cost/DoS control surface |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-05-10 | Elevation of privilege | prompt injection in channel text | mitigate | Channel text is placed ONLY in the user turn (data channel); system prompt (extract_v1.md) is static + cached + declares user content as data not instructions; output is constrained to the ExtractionResult tool schema (Mode.TOOLS) so injected "ignore instructions" text cannot change the output shape |
| T-05-11 | Tampering | hallucinated/fabricated fields | mitigate | response_model=ExtractionResult + irrelevant_fields_must_be_null validator + temperature=0; fabrication cannot bypass the schema; rule-based fallback forces confidence<0.5 → review |
| T-05-12 | Denial of service | unbounded token spend (cost DoS) | mitigate | check_and_reserve_tokens is a hard pre-call gate against LLM_DAILY_TOKEN_LIMIT with atomic INCRBY + rollback; the budget cap is the security control (security_threat_model) |
| T-05-13 | Information disclosure | ANTHROPIC_API_KEY | mitigate | Read from settings only; never logged; raw_response stored is the completion, not the key |
| T-05-14 | Denial of service | oversized forwarded message | mitigate | prepare_message_text truncates to 2000 tokens before the call (G6) |
</threat_model>
