<objective>
Implement the three UZEX collectors (offers in sum/currency/import sections, quotation/contract lists, and the concluded-deals registry) as registered SourceAdapters, plus the immutable deduplicated raw pipeline they write into. Per the collector principle, the adapters do NOT parse meaning — they fetch HTML via the shared http_client, extract table rows with selectolax using selectors/column-mapping from `sources.config` (never hardcoded — UZEX layout is the #1 external risk), and save each row to `raw_items.payload` with sha256 dedupe. The signals write is a separate task (02-05). The first task captures HTML fixtures as the regression base against layout drift.

Purpose: This is REQ-uzex-parser's fetch half — it produces immutable, deduplicated raw_items on the beat schedule. The fixtures make the parser testable offline and are the documented response to UZEX re-skinning.
Output: `app.ingest.uzex` adapters + parser, `raw_pipeline.save_raw_items`, the real `uzex_fetch_*` Celery tasks (replacing 02-01 placeholders), and committed HTML fixtures.
</objective>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| UZEX website → adapter (HTML) | UNTRUSTED markup: malformed encodings, entity expansion, oversized tables, hostile cell content |
| parsed row → raw_items.payload (jsonb) | untrusted strings persisted as JSONB payload |
| source.config → selectors | admin-supplied selectors drive what gets extracted |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-02-11 | Denial of Service | malicious/huge UZEX HTML OOMs the selectolax parse | mitigate | Outbound fetch goes through http_client size cap (T-02-08); cap the number of rows parsed per page and per-cell string length before persisting |
| T-02-12 | Tampering / Injection | untrusted cell text persisted to raw_items.payload (jsonb) | mitigate | Persist via bound parameters / ORM only; payload is opaque JSONB (no SQL string interpolation); content_normalized strips control chars before hashing |
| T-02-13 | Tampering (XML/HTML entity expansion) | entity-bomb in fetched HTML | mitigate | selectolax (lexbor) does not expand external entities like an XML parser; cap input size via the http_client body cap |
| T-02-14 | Spoofing | UZEX layout drift silently changing field meaning | mitigate | Selectors live in sources.config (not code) + committed HTML fixtures form the regression base; a layout change fails the fixture test before reaching prod |
| T-02-SC | Tampering | pip install `selectolax` (new dependency, [ASSUMED]) | mitigate | Blocking human-verify checkpoint (Task above) verifies selectolax on pypi.org/project/selectolax before install; [SLOP] would be rejected |
</threat_model>
