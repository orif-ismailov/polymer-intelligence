<objective>
Deliver the FX rates loop and the rule-based parse task that turns UZEX raw_items into signals. The CBU adapter imports the official daily CBU RUz rate into fx_rates; `convert_amount` computes conversions on read while preserving the original currency (never storing converted values). The `parse_raw_item` task is the meaning layer: it reads a pending raw_item's payload, matches the product via the synonyms dictionary, extracts the grade via regex, and writes a normalized signals row — routing polymer-relevant rows to signals, non-polymer to raw_items status='irrelevant', and unrecognized goods to the manual_classification_queue (NOT a source_failure). Every parse is journaled in parse_runs with model=NULL (rule-based).

Purpose: This completes REQ-fx-rates and the signals half of REQ-uzex-parser. After this, real polymer positions appear in signals with correct fields and FX conversion is available to the dashboard.
Output: `cbu_rates` adapter + `fetch_cbu_rates` task (own task module to avoid a same-wave file conflict with 02-04's UZEX tasks), `fx_service` (upsert + on-read convert), `parse_raw_item` task, `signal_service.create_signal_from_parse`, and the grade regex matcher in the service layer (own file, no overlap with 02-04's uzex package).
</objective>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| CBU JSON API → fx_rates | external JSON parsed into numeric rates (type-confusion / malformed-number risk) |
| raw_items.payload (untrusted) → signals | untrusted UZEX strings coerced into Decimal/typed signal fields |
| parsed text → DB writes | product/grade/counterparty text persisted |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-02-15 | Tampering (type confusion) | CBU rate values / UZEX price-volume strings coerced to Decimal | mitigate | Strict Decimal parsing with try/except → None on malformed input; reject NaN/Inf; never use eval/float-of-untrusted for money |
| T-02-16 | Tampering (SQL injection) | product/grade/counterparty text into signals & fx upsert | mitigate | ORM / bound parameters only; no f-string SQL anywhere in parse or upsert paths |
| T-02-17 | Denial of Service | a single hostile raw_item payload aborting the whole parse batch | mitigate | parse_raw_item is per-item (one raw_item_id per task); failures are caught + journaled to parse_runs status='error' without crashing siblings |
| T-02-18 | Repudiation | rule-based parses untraceable | mitigate | Every parse writes a parse_runs row (parser, model=NULL, status, result) — full provenance journal |
| T-02-SC | Tampering | npm/pip/cargo installs | accept | No new package installs (selectolax/httpx already present from 02-04/pyproject) |
</threat_model>
