<objective>
Create the synonyms dictionary table (the Phase-1 → Phase-2 carryover: synonyms.json was seeded-ready but the locked DDL v1.1 has no synonyms table), a manual-classification queue table for unrecognized goods, the migration that creates both, the seeder that loads synonyms.json idempotently, and the relevance service that maps raw product text to a product_id. This dictionary is what drives Phase-2 relevance routing: polymer-relevant rows → signals (02-05), non-polymer → raw_items status='irrelevant' (02-05), unrecognized goods → the manual-classification queue with NO source_failure alert (REQ-uzex-parser).

Purpose: The UZEX parser (02-05) cannot decide relevance without this dictionary and queue. The dictionary must be admin-top-up-able (additive rows, not code edits) per SC#4.
Output: `product_synonyms` + `manual_classification_queue` tables (via a NEW Alembic migration revising 0001), ORM models, an idempotent seeder, and `relevance_service.match_product()`.
</objective>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| seed file → DB | synonyms.json (repo-controlled) is loaded into product_synonyms |
| admin input → product_synonyms | admin-added synonym rows (Phase-4 UI) become match inputs; the data is trusted-internal but normalization must be injection-safe |
| raw product text → relevance lookup | untrusted UZEX product text is normalized and matched against the dictionary |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-02-04 | Tampering (SQL injection) | match_product / queue_for_classification lookups on untrusted product text | mitigate | All DB access uses bound parameters (SQLAlchemy `text(...).bindparams` or ORM), never f-string SQL; normalize_term does not eval/format SQL |
| T-02-05 | Denial of Service | unbounded product_text length pushed into the queue | mitigate | Truncate `product_text` to a bounded length (e.g. 512 chars) before queueing so a hostile oversized UZEX cell cannot bloat the queue row |
| T-02-06 | Tampering | unique constraint bypass on re-seed creating dup synonyms | mitigate | UNIQUE(synonym_norm) + ON CONFLICT DO NOTHING guarantees idempotent seeding and dedup |
| T-02-SC | Tampering | npm/pip/cargo installs | accept | No new package installs in this plan |
</threat_model>
