<objective>
Build the backend Live Market Feed: a keyset-paginated `GET /feed` over `v_live_feed` that
stays ≤500 ms at 1M signals, plus the SSE `GET /feed/stream` endpoint (Redis pub/sub) that
pushes new entity IDs so the dashboard refreshes without reload. This is the Wave-1 backend
foundation that the feed screen (04-03) consumes.

team's primary read surface. Keyset pagination + SSE are the locked mechanisms.

router registered in `main.py`.

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Browser → /feed, /feed/stream | Untrusted client requests cross into the DB read path |
| Redis pub/sub → SSE generator | Internal event bus; only backend tasks publish |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-04-01 | Spoofing | GET /feed, /feed/stream | mitigate | `Depends(get_current_staff_user)` — verified JWT; 401 without (asserted in tests) |
| T-04-02 | Tampering (SQLi) | feed filter params | mitigate | All filters bound as sa.text params, never string-interpolated; cursor passed as typed query params |
| T-04-03 | Denial of Service | GET /feed pagination | mitigate | `limit` capped at `le=200`; keyset (not OFFSET) keeps query ≤500 ms at 1M rows; no full-scan path |
| T-04-04 | Info Disclosure | FeedItem columns | accept | v_live_feed is internal team data; no secret/config columns selected (only normalized signal fields) |
| T-04-SC | Tampering | npm/pip installs | accept | No package installs in this plan (redis>=5.0.0 already in pyproject) |
</threat_model>
