<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Web App → backend /webapp/* | The client must attach initData on every request; the backend (03-01/03-02) verifies it. The frontend never trusts its own state for identity. |
| User files → FileUploader | Client-side validation is UX only; the backend (03-01) is authoritative. |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-03-15 | Spoofing | client sends requests without initData | mitigate | api/client.ts attaches X-Telegram-Init-Data on every call; backend rejects missing/invalid (Task 1 + 03-01/02) |
| T-03-16 | Denial of service | huge/many file selection client-side | mitigate | FileUploader rejects >5 / >10 MB / wrong-MIME before upload; backend re-validates (Task 2 + 03-01) — defense in depth |
| T-03-17 | Tampering | client bypasses client-side file checks | accept | Client-side checks are UX only; the backend magic-byte/size/count validation (03-01/02) is authoritative — client bypass cannot persist a bad file |
| T-03-SC | Tampering | npm installs (react-router-dom, lucide-react) | mitigate | Blocking human legitimacy checkpoint (Task 0) — npmjs.com verification before install |
</threat_model>
