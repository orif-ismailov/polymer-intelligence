<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| browser → /api/v1/auth/* | Untrusted credentialed requests; CORS controls which origins may drive credentialed (cookie-bearing) calls; the httpOnly refresh cookie crosses here |
| attacker → /api/v1/auth/login | Untrusted login attempts probing for valid accounts via response-timing differences |
| operator config → app startup | A weak/short JWT_SECRET supplied via env weakens HS256 token integrity for the whole service |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-03-01 | Information Disclosure (user enumeration) | auth_service.authenticate unknown-user path | mitigate | Replace malformed dummy hash with `dummy_verify` against a real precomputed argon2 hash so the unknown-user path performs full KDF work; wrong-password and unknown-user timings converge, closing the timing oracle |
| T-03-02 | Tampering (token forgery) | JWT HS256 signing secret | mitigate | field_validator rejects JWT_SECRET < 32 chars at startup, raising the brute-force cost floor for HS256 tokens |
| T-03-05 | Information Disclosure (credential theft) | CORS + httpOnly refresh cookie | mitigate | Drive allow_origins from an explicit settings list with allow_credentials=True (never wildcard) so browsers actually attach the credentialed refresh cookie only for trusted origins; wildcard+credentials is both insecure and non-functional |
| T-03-SC | Tampering | dependency installs | accept | No new packages added; argon2-cffi and pydantic-settings already audited in 01-01/01-03 |
</threat_model>
