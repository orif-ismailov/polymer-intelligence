<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| operator → container env | Secrets (.env) injected into containers; must never be committed |
| internet → /health | Unauthenticated endpoint; must not leak secrets or internals |
| app → postgres/redis | Connection strings carry credentials; sourced only from env |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-01-01 | Information Disclosure | secrets in repo | mitigate | Settings reads secrets from untracked `.env`; `.gitignore` excludes `.env`/`*.session`; `.env.example` holds placeholders only; no secret literals in source (acceptance grep) |
| T-01-02 | Information Disclosure | `/health` response | mitigate | Health returns only status enums (ok/error) for db/redis, never connection strings, versions, or stack traces |
| T-01-03 | Tampering | docker-compose secrets | mitigate | Compose uses `env_file` referencing the external `.env`; no inline credentials |
| T-01-04 | Denial of Service | unauthenticated `/health` | accept | Low-value, cheap endpoint behind nginx in prod; rate limiting deferred to deploy phase |
| T-01-SC | Tampering | pip installs (pyproject deps) | mitigate | All deps are well-known PyPI packages locked by the dev-spec stack; no [ASSUMED]/[SUS] packages introduced (no third-party legitimacy gate needed for the canonical stack) |
</threat_model>
